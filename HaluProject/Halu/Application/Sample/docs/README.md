# Sample アプリ 設計書一式（納品物の形式の見本）

本フォルダは Halu フレームワークの実装リファレンス「Sample（受注管理システム（サンプル））」に付随する設計書一式で、Halu 標準の開発プロセスで作成する**納品物の形式の見本**として公開しています。
Sample アプリの実装の大半は標準プロセスの確立前に作られ、設計書は 2026-07 に実装から起こしたうえで承認プロセスに載せたものです。したがって本一式は「文書の形式・粒度・相互参照の見本」であり、AI 主体開発の方法論をゼロから適用した実証ではありません。

## 収録内容

| フォルダ | 内容 |
|---|---|
| `10_要件定義/` | 要件定義書（業務要件 REQ・非機能要件 NFR） |
| `11_データモデル/` | データモデル設計書（ER図・テーブル定義・業務ルール） |
| `20_基本設計/` | 共通仕様（`common.md`。項目語彙・メッセージ・共通挙動の正本）と画面・帳票・バッチごとの基本設計書 |
| `30_テスト仕様/` | 画面・帳票・バッチごとのテスト仕様書（V/O/S/T 分類のケースと実施記録）、`evidence/`（実施証跡）、`テストデータ/` |
| `60_リバース仕様書/` | 実装（JSON 定義）から機械生成した機能一覧・ＣＲＵＤ表・テーブル定義書 |

開発側で管理している変更管理台帳・承認記録簿・UI デザイン適用の指示書・品質集計・監査レポートは公開版には含めていません。

## 文書内の管理番号について

各文書の改訂履歴・特記事項に現れる次の番号は、開発側（非公開リポジトリ）の管理番号です。公開版からは参照先を辿れませんが、変更の経緯を示す識別子としてそのまま残しています。

| 記号 | 意味 |
|---|---|
| `C-0NN` | 変更管理台帳の変更ID（仕様変更・不具合・指摘の起票番号） |
| `A-0NN` | 承認記録簿の承認番号（人間による承認イベント） |
| `D-0NN`・`Q-0NN` | UI デザイン適用の案件番号・決定依頼番号 |
| `REQ-NNN`・`NFR-NNN` | 要件定義書の要件ID・非機能要件ID（本一式内で辿れます） |
| `Issue #NN` | 開発リポジトリの課題番号 |
| `生成日時点のコミット: xxxxxxx` | 生成元定義ファイルの版を示す開発リポジトリのコミット |

## 表記の約束

- ヘッダ表の「作成者」は組織名（`TILLS`）、承認欄・改訂履歴の確認者は役割名（`依頼者`・`開発者`）で書いています。
- 改訂履歴の「作成/改訂者」欄の `AI（依頼者確認）` は、AI が起案し人間が確認・承認した改訂を示します。
- テスト仕様書の「前提ゲート記録」（3章）は、ケース実施に先立つ機械検証（定義ファイルの静的整合チェック・API 疎通確認）の実測を、実施記録は AI によるブラウザ実走の結果を記録しています。
- 公開初版では全文書の版数を `1.0` に統一しています（開発中の改訂経緯は開発リポジトリで管理）。テスト実施記録・実施証跡の日付が初版日より前になるのは、実施→承認→初版発行の順によるものです。
- テスト仕様書のうち BatchDivisionList・BatchOrderUpload・ProductListMainte には、公開時点で未解消の NG（フレームワーク側の不具合。開発リポジトリの Issue #88・#91。次版で修正予定）が実施記録にそのまま残っています。
