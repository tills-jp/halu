## 0. 種別決定の経緯

タブ切替式のメニューカード一覧から各画面へ遷移するだけの画面であり、検索・登録更新等のデータ編集機能は持たない。Haluの標準5タイプには該当せず、専用の`TabMenuControllerMixin`/`TabMenuModelMixin`/`TabMenuViewMixin`（Halu開発ガイド『ミックスイン』参照）を使用するため、種別は「メニュー」とする。

---

## 1. 要件

| 要件ID | 区分 | 要件 | 背景・理由 |
|--------|------|------|-----------|
| REQ-001 | 表示 | ログイン中のユーザ氏名をヘッダーに表示する | ログイン中ユーザを常に把握できるようにするため tabMenu.view.mixin-1.0.0.js／Header.svelteの実装からの逆算。なお、ログイン日時表示はD-011（2026-07-27 UAT承認）で廃止済み（データ取得・sessionStorageは不変） |
| REQ-002 | 遷移 | メニューカードをクリックすると対象画面へ遷移する | 各画面パターンのサンプルを一覧から呼び出せるようにするため 実装からの逆算 |
| REQ-003 | 表示 | メニュー項目をタブ（受注管理／マスタ／システム）で業務分類表示する（2026-08-02 C-042でパターン分類から業務分類へ変更） | 画面数が多くなった場合の一覧性・分類のため 実装からの逆算 |
| REQ-004 | 記録 | 画面表示時・メニュー項目クリック時・ログアウト時にユーザのアクセスログ（ログ情報）を記録する | 利用状況の追跡・監査のため tabMenu.model.mixin-1.0.0.jsの実装からの逆算 |
| REQ-005 | 遷移 | ヘッダー右上の「ログアウト」ボタンでログオフのアクセスログ（`term`）を記録し、セッションをクリアしてLoginへ遷移する | ログイン画面へ戻り再認証させるため（D-002/C-001、`docs/変更管理台帳.md`参照）。ログオフ記録はIssue #27で追加（それまでは記録されていなかった） |
| REQ-006 | 操作性 | ログアウト操作はヘッダー右上の「ログアウト」の1経路のみとする（タブ上部の旧ログアウトボタン`id="戻る"`とEscキー経路はIssue #27で撤去） | C-002ではCSS非表示化のみだった旧経路（Escキーで発火・遷移先がブラウザ履歴依存・ログオフ記録の有無がヘッダー経路と食い違う）を物理削除し、ログアウトの挙動を1つに揃えるため |

## 5. 特記事項

- **初期表示**：画面表示時、セッションストレージに「ターゲットタブ」が保存されていればそのタブを復元表示し、無ければ`init`トランザクションを実行してアクセスログ（ログ情報）を1件登録した上でタブ1を表示する。
- **アクセスログ（ログ情報テーブル）**：`init`（画面表示）・`userinfo`（メニュー項目クリック）・`term`（ヘッダー右上のログアウト）の各トランザクションで、`ログ情報`テーブルへユーザＩＤ・アクセス日時・画面名・host/hostname/port/request/code/browser/version/lang/platform/useragent/referer/domain/screen_w/screen_h/screen_colを1件INSERTする。ブラウザ・端末情報の収集が目的で、`TabMenuModelMixin.setDisplayInfo`が`navigator`/`location`/`screen`オブジェクトから値を編集する（`term`は`Header.svelte`が同じ項目・同じ値を設定する）。
- **ログアウト経路は1系統（Issue #27・2026-09-15）**：ヘッダー右上の「ログアウト」（`Header.svelte`の`handleLogout`）が`StartMenu_term_tran.json`を取得して`term`（ログオフ記録。画面名「ログオフ（メニュー終了）」）を`Halumain`へ送信し、応答後にセッションストレージを全クリアして`Login`へPOST遷移する。記録の失敗（通信エラー等）ではログアウトを止めない（コンソールに警告のみ）。ヘッダーは全画面に載るため、メニュー以外の画面からのログアウトも記録される。C-002でCSS非表示化のみだった旧ログアウトボタン（`id="戻る"`）とEscキー経路（`term`後に`previousTransition`で履歴を戻る）は撤去した。`tabMenu`ミックスインの`on戻る`／`on終了処理*`と`term`定義は、他アプリ（Svelteヘッダー無し・「戻る：Esc」ボタンあり）が使う共通パターンのため残置。
- **本画面固有のdataset**：`header`レコードに実質的な入力項目はなく、`ダミー`という名称のプレースホルダ項目のみを持つ（メニュー画面はサーバーとの入力データ授受を伴わないため）。
- **freesql／doRun**：本画面では使用していない（`genesql`のみ）。
- **疑義（修正禁止・報告のみ）**: 3.1（受注管理タブ）に「取込エラー一覧」（OrderUploadErrorList）のカードが記載されていないが、実装（`StartMenu/index.html`）には当該カードが存在し、common.md 1.1・OrderUploadErrorList.md 5章も掲載済みとしている（C-041）。設計書の記載漏れ。
- **疑義（修正禁止・報告のみ）**: 3.2（マスタタブ）は「商品一覧登録」を遷移先なしの非活性カードとしているが、実装では`name="Sample/Html/Apps/ProductListMainte"`が設定され`disabled`も外れている（common.md 1.1・ProductListMainte.md 5章のとおり2026-08-04に有効化済み）。設計書の記載が実装より古い。

## 6. 画面遷移

| 遷移元 | 遷移先 | トリガ | 受け渡し項目 |
|--------|--------|--------|--------------|
| Login | 本画面 | 認証成功（ユーザ.メニュー名="StartMenu"。common.md 1章 画面遷移図） | セッションストレージ（ユーザＩＤ・ユーザ名称・メニュー名・ログイン時刻・ログイン和暦。Login.md REQ-006） |
| 本画面 | OrderList | 受注管理タブの「受注一覧」カードクリック（common.md 1.1） | - |
| 本画面 | OrderUpload | 受注管理タブの「受注データアップロード」カードクリック（common.md 1.1） | - |
| 本画面 | OrderUploadErrorList | 受注管理タブの「取込エラー一覧」カードクリック（common.md 1.1・C-041。5章の疑義参照） | - |
| 本画面 | BatchList | 受注管理タブの「バッチ一覧」カードクリック（common.md 1.1） | - |
| 本画面 | CustomerListMainte | マスタタブの「顧客一覧登録」カードクリック（common.md 1.1） | - |
| 本画面 | ProductListMainte | マスタタブの「商品一覧登録」カードクリック（common.md 1.1。5章の疑義参照） | - |
