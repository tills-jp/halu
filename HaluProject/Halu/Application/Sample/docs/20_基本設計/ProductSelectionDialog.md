## 0. 種別決定の経緯

受注明細一覧（OrderDetailListMainte）の明細行から商品を指定するための選択ダイアログ。`DataSelectionDialog*.mixin` を使い、既存の顧客選択ダイアログ（CustomerSelectionDialog）を正典として同じ構成で実装する。表示方式は**iframe分離方式**（`dialogtype: "iframe"` 指定）とし、呼び出し元はフルページ再ロードされない。方式の詳細は Halu開発ガイド『選択ダイアログ』 を参照。

CustomerSelectionDialogとの違いは**検索条件を持つこと**（2026-08-04依頼者決定）。商品はマスタ件数が増えやすく、ページ送りだけでは探しにくいため。

---

## 1. 要件

| 要件ID | 区分 | 要件 | 背景・理由 |
|--------|------|------|-----------|
| REQ-001 | 表示 | 有効な商品（削除フラグ='0'）を商品コード順に一覧表示する | 商品はコード体系で探すという想定（C-048のUATで商品一覧登録の並び順として承認済みの判断を踏襲） |
| REQ-002 | 検索 | 商品コード・商品名称で絞り込める（いずれも部分一致・任意入力） | 商品件数が増えても探せるようにするため。一致方式はcommon.md 2.3.1の既定に従う |
| REQ-003 | 表示 | 1ページ25件でページ送りできる（最初・前・次・最後） | 選択ダイアログの共通挙動（DataSelectionDialogパターン） |
| REQ-004 | 選択 | 一覧の行を選択して「選択」を押すと、呼び出し元の明細行へ**商品ＩＤ・商品名称・標準単価（受注単価として）**を引き渡す。行が選択されていない状態で「選択」を押した場合は、警告ダイアログ（MSG-006「行が選択されていません。選択して下さい。」）を表示し、呼び出し元への値返却・ダイアログのクローズを行わない（フレームワーク共通`check行選択`によるガード） | 受注明細に商品ＩＤ（NOT NULL・FK）を設定するため。要件定義書REQ-014-3。未選択ガードは顧客選択ダイアログ（CustomerSelectionDialog）REQ-003と同じ既定 |
| REQ-005 | 操作性 | 選択（F1）・検索（F5）・ページ送り（F9〜F12）・閉じる（ESC）をPFキーで操作できる | キーボード中心の操作に慣れたユーザへの配慮（顧客選択ダイアログと同じ割当） |

| 2 | 検索商品名称 | input | text | 100 | - | | 商品.商品名称の部分一致検索。空欄なら絞り込まない |

| 5 | 最大ページ | 内部 | number | - | - | | サーバー側afterフック`getMaxPageCountOfProductSelection`が算出 |
| 6 | トータル件数 | 内部 | number | - | - | | `total_count`SQLのCOUNT(*) |

## 4. 操作

| 操作 | キー | 動作 | 遷移先 |
|------|------|------|--------|
| 選択 | F1 | 選択行の商品ＩＤ・商品名称・受注単価を呼び出し元へ引き渡してダイアログを閉じる。未選択の場合は警告ダイアログ（MSG-006）を表示し、値返却・クローズを行わない | 呼び出し元（OrderDetailListMainte） |
| 検索 | F5 | 検索条件で1ページ目から再照会する | - |
| クリア | - | 検索条件欄をクリアする（**一覧はそのまま。再検索はしない**） | - |
| 最初・前へ・次へ・最後 | F9・F10・F11・F12 | ページを移動して再照会する | - |
| 閉じる | ESC | 選択せずにダイアログを閉じる | 呼び出し元（OrderDetailListMainte） |
| 一覧の行クリック | - | 選択行の背景色を変え、行の値をセッションストレージへ退避する | - |

## 5. 特記事項

- **返却値の項目名は呼び出し元のdataset項目名と一致させる必要がある**（フレームワークの制約）。呼び出し元の`selectStorageResponseData.dataname`に列挙した項目名で、ダイアログ側がセッションストレージへ退避した値（`sessionStorageDetailKey`）を読み出す仕組みのため。したがって本ダイアログのdetailレコードは、表示用の`商品コード`／`標準単価`とは別に、呼び出し元の項目名である`商品ＩＤ`・`商品名称`・`受注単価`を持つ（`受注単価`の値は`標準単価`と同一）。顧客選択ダイアログが`顧客ＩＤ一覧`（表示用）と`検索顧客ＩＤ`（返却用）を並べているのと同じ理由。
- **呼び出し元からの引き渡しデータは無し**（`selectStorageRequestData.dataname`は空配列）。フレームワークの引き渡しは常に`value[0]`（先頭行）を読むため明細行ごとの値を渡せず、渡す意味のある値が無い。呼び出し元・ダイアログ側とも`dataname.length > 0`のガードがあるため空配列で安全に動作する（2026-08-04 実走確認済み）。
- 検索条件はサーバー側フック`setSql_ProductSelectionDialog`が`where`句の`&&`を置換して組み立てる（UserList・OrderListと同方式）。値の埋め込みには必ず`commons.sqlescape.escapeSqlLiteral`を通す（common.md 2.4）。
- 選択済みの商品を再選択する経路は特に制限しない（同じ商品を複数明細行に指定できる。数量をまとめるかどうかは業務判断であり画面では制御しない）。
- パターン確認用の「警告・確認・実行・サーバ」ボタンは本画面には設けない（顧客選択ダイアログにあった同ボタンも C-076 で削除され、両ダイアログのボタン構成は同一になった）。

## 6. 画面遷移

| 遷移元 | 遷移先 | トリガ | 受け渡し項目 |
|--------|--------|--------|--------------|
| OrderDetailListMainte | ProductSelectionDialog | 明細行ごとの「選択」ボタン（iframe分離方式のモーダル表示） | -（呼び出し元の`selectStorageRequestData.dataname`は空配列＝引き渡しなし。5章参照） |
| ProductSelectionDialog | OrderDetailListMainte | 「選択：F1」（値を返す）／「閉じる：Esc」（値を返さない） | detail.商品ＩＤ・商品名称・受注単価（本画面の`sessionStorageDetailKey`へ退避した値を、呼び出し元の`selectStorageResponseData.dataname`が同名で読み出す。「閉じる」時は返却なし） |

メニュー画面（StartMenu / AdminMenu）からの直接起動は持たない（common.md 1.1に掲載行を持たず、common.md 1.2の「OrderDetailListMainte → ProductSelectionDialog」のみが呼び出し経路）。本ダイアログを呼び出す画面はOrderDetailListMainteのみ。
