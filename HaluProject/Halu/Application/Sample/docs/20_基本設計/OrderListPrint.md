## 1. 要件

| 要件ID | 区分 | 要件 | 背景・理由 |
|--------|------|------|-----------|
| REQ-001 | 出力 | OrderList画面の検索条件（顧客・受注日FROM/TO）に合致する受注の一覧を「受注一覧表（Ｈ）」としてPDF出力する | 複数受注をまとめて紙・PDFで確認・共有する運用のため |
| REQ-002 | 出力 | OrderList画面の検索条件に合致する受注ごとに、ヘッダ情報＋明細行を「受注一覧表（ＨＭ）」としてPDF出力する（受注番号ごとに帳票キーが分かれ、複数受注分がまとめて出力される） | 受注1件ごとの明細内容を個別の帳票として確認する運用のため |
| REQ-003 | ページング | 受注一覧表（Ｈ）は1ページ20行の明細行を持ち、全体を通したページ番号を付与する | 帳票のページ管理のため（`pagelines: 20`、`page_headerH`は`get_totalPageNo()`使用） |
| REQ-004 | ページング | 受注一覧表（ＨＭ）は受注番号（printKey）ごとに1ページ10行の明細を持ち、受注ごとにページ番号がリセットされる | 受注明細書として受注単位で完結させるため（`pagelines: 10`、`page_headerHM`は`get_currPageNo()`使用） |

## 4. 抽出条件・並び順

| 項目 | 内容 |
|------|------|
| 出力条件（画面から受け取る項目） | **printParam**（両帳票共通）: 検索顧客ＩＤ（顧客選択ダイアログで選択した顧客ＩＤ）・検索顧客氏名・検索受注日カラ・検索受注日マデ（いずれもOrderList画面の検索条件）。**printKey（Ｈ）**: 処理日時のみ（1行）。検索条件に合致する全件を1バッチで帳票サーバーへ渡し、20行ごとの改ページはフレームワーク（`pagelines`）が行う（C-066で暫定対応のオフセット方式＝printKeyがページ数分の行を持ち `LIMIT ? OFFSET ?` で読み出す構成を撤去。ページ数計算が検索条件を無視して明細0行の空ページを生成していた）。**printKey（ＨＭ）**: 受注番号の一覧（`OrderList_printHM_sql.json`のprintKeyＳＱＬがOrderListの検索条件に合致する受注番号を取得。複数件になり得る）。受注番号1件ごとに1帳票（ページ番号はリセット）を生成し、全件分を1つの出力ファイルにまとめる |
| 抽出条件（ＳＱＬ上の絞り込み） | **Ｈ**: `setSql_OrderListPrint_printH` が genesql の `where` の `&&` を置換し、検索顧客ＩＤ（`cst.顧客ＩＤ = '値'`）・**検索顧客氏名（`cst.顧客氏名 LIKE '%%値%%'`・部分一致。画面の一覧検索と同じ。C-066で追加）**・検索受注日カラ（`hdr.受注日 >= '値'`）・検索受注日マデ（`hdr.受注日 <= '値'`）の4条件を反映する（未指定の条件は句を生成しない＝その条件なし。画面の `setSql_OrderList` と同じ条件になる）。受注番号・顧客氏名・受注日でGROUP BYし明細数をCOUNTする。**ＨＭ**: ページヘッダは `A.受注番号 = ?`（printKeyの受注番号）、明細は `受注番号 = ?`（画面の検索条件による絞り込みは、検索顧客氏名を含めprintKey取得時＝`setSql_OrderList` で完了している） |
| 並び順 | **Ｈ**: `hdr.受注番号, hdr.受注日`（`OrderListPrint_printH_sql.json` detail の `order`）。**ＨＭ**: 帳票の出力順＝printKeyの取得順 `hdr.受注番号, hdr.受注日`（`OrderList_printHM_sql.json`）、明細は `明細番号`（`OrderListPrint_printHM_sql.json` detail の `order`） |
| 対象データ（主なテーブル） | 受注ヘッダ・受注明細・顧客（顧客氏名の取得はLEFT OUTER JOIN。CRUDの一覧はリバース出力のＣＲＵＤ表を正とする） |

## 5. 特記事項

- 本帳票は`printH`/`printHM`の2トランザクションを持つ。呼び出し元は`OrderList`画面の「受注一覧(ヘッダー)」「受注一覧(ヘッダー・明細)」ボタン。トランザクション定義・SQL定義は`Json/Apps/OrderListPrint/`配下、フックは`Server/Apps/OrderListPrint/OrderListPrint_model.py`（SQL条件組み立て）・`OrderListPrint_form.py`（ページ番号設定）。
- `freesql`は本帳票では使用していない（すべて`genesql`または`nosql`）。`OrderListPrint_model.py.setSql_OrderListPrint_printH`が`genesql`の`where`句の`&&`をリクエストデータから組み立てた条件文字列で置換する、Sample標準のフック実装パターンに準拠している。
- **受注一覧表（Ｈ）の絞り込み条件（C-066で是正済み・2026-09-14）**: 旧実装の `setSql_OrderListPrint_printH` は検索顧客ＩＤ・検索受注日カラ・検索受注日マデの3条件のみを反映し、検索顧客氏名を無視していたため、顧客氏名で絞り込んだ画面より広い範囲が帳票に出力されていた（Issue #26）。C-066で検索顧客氏名の部分一致を追加し、画面の一覧検索（`setSql_OrderList`）と同じ4条件になった。あわせて、Issue #16 の暫定対応（printKeyのオフセット方式。7f0d4a7）を撤去し、Ｈの改ページはフレームワークの `pagelines` 制御に一本化した（真因の `excelcontroller.py` の TypeError は Issue #59 で修正済み）。
- 受注一覧表（ＨＭ）はキー情報（`printKey`）としてOrderList画面の検索条件に合致する受注番号の一覧を`OrderList_printHM_sql.json`側で取得し（`setSql_OrderList('header', 'printKey', 'genesql')`）、帳票サーバー側の`OrderListPrint_printHM_sql.json`では受注番号ごとにヘッダ・明細を再検索する2段階の構成になっている（py_report.mdの「printHM: printKeyに複数行の受注番号を渡す」構成に合致）。

## 6. 帳票仕様

（実装から採取した現状の仕様。テンプレート（xlsx）の`pageSetup`・tran.jsonの`excelinfo`・`OrderListPrint_form.py`が出所）

| 項目 | 内容 |
|------|------|
| 用紙・向き | A4 縦（両テンプレートとも `pageSetup paperSize="9" orientation="portrait"`。paperSize=9がA4） |
| 改ページ条件 | **Ｈ**: 明細20行ごと（tran.jsonの`pagelines: "20"`・`rowposition: "8"`・`movedown: "1"`）。**ＨＭ**: 受注番号（printKey）ごとに帳票が分かれ、その中で明細10行ごとに改ページ（`pagelines: "10"`・`rowposition: "9"`） |
| 集計行 | なし（小計・合計行を持たない）。ＨＭはページヘッダに受注ヘッダ.受注金額合計を「合計金額」として印字し、Ｈは受注ごとの明細数をCOUNTで表示するのみ |
| ヘッダ・フッタ | Excelのヘッダ／フッタ機能は未使用（テンプレートに`headerFooter`要素なし）。ページ番号はシート内セルへ設定する（Ｈ=E1・全体通しページ番号 `get_totalPageNo()`／ＨＭ=I1・受注番号ごとのカレントページ番号 `get_currPageNo()`。いずれも`OrderListPrint_form.py`）。Ｈは出力条件（検索顧客氏名・受注日ＦＲＯＭ／ＴＯ）をB5・C5・D5へ印字する。出力日時の印字はなし |
| 0件時の挙動 | Ｈ: 検索条件に合致する受注が0件でも、ページヘッダ（検索顧客氏名・受注日FROM/TO）だけを印字した1ページを出力する（明細0行・エラーなし）。ＨＭ: printKey の受注番号が0件のときも、受注番号・顧客氏名・受注日・合計金額・明細がすべて空の1ページを出力する（エラー・MSG-018 にはならない。理由: 受注番号の request 値が空文字1要素として渡り帳票生成が1回実行されるため）。画面側（`OrderList.controller.js`）・ＳＱＬに0件時の中止処理は持たない。2026-09-24 実測で確定（承認記録簿 A-034） |
| ファイル名規約 | 固定名（`OrderListPrint_printH.xlsx`／`OrderListPrint_printHM.xlsx` と同名のPDF）。tran.jsonの`excelinfo.savefile`で指定し、出力先は `Sample/DownLoad/Apps/OrderListPrint/`。**出力のたびに同名ファイルを上書きする**（日時等の付与はしない。Halu開発ガイド『帳票実装』 6章） |
| 大量件数時の扱い | 件数上限によるエラー・分割の制御はなし（ページ分割のみ）。Ｈは検索条件に合致する全件を1バッチで渡しフレームワークが20行ごとに改ページする（C-066で `LIMIT ? OFFSET ?` のページ単位読み出しを撤去）、ＨＭはprintKeyの受注番号ごとに帳票を生成して1ファイルへまとめる（件数上限を設けないことを現行仕様として確定。2026-10-05 A-037） |
