## 0. 種別決定の経緯

StartMenuと同一のタブ切替式メニューカード画面であり、`TabMenuControllerMixin`/`TabMenuModelMixin`/`TabMenuViewMixin`を共用する。ユーザ.メニュー名="AdminMenu"のユーザがログイン成功時に遷移する画面であるため、業務上は「管理者用メニュー」と位置づけられる。種別はStartMenuと同じく「メニュー」とする。

---

## 1. 要件

| 要件ID | 区分 | 要件 | 背景・理由 |
|--------|------|------|-----------|
| REQ-001 | 認可 | ユーザ.メニュー名="AdminMenu"のユーザはログイン成功時に本画面へ遷移する | 一般ユーザ（StartMenu）と管理者ユーザで遷移先メニューを分けるため login.model.mixin-1.0.0.jsの実装からの逆算 |
| REQ-002 | 表示 | ログイン中のユーザ氏名をヘッダーに表示する | ログイン中ユーザを常に把握できるようにするため 実装からの逆算。なお、ログイン日時表示はD-011（2026-07-27 UAT承認）で廃止済み（データ取得・sessionStorageは不変） |
| REQ-003 | 遷移 | メニューカードをクリックすると対象画面へ遷移する | 各画面パターンのサンプルを一覧から呼び出せるようにするため 実装からの逆算 |
| REQ-004 | 記録 | 画面表示時・メニュー項目クリック時・ログアウト時にユーザのアクセスログ（ログ情報）を記録する | 利用状況の追跡・監査のため 実装からの逆算 |
| REQ-005 | 遷移 | ヘッダー右上の「ログアウト」ボタンでセッションをクリアしてLoginへ遷移する | ログイン画面へ戻り再認証させるため（D-002/C-001） |

## 2. 画面モック

```
┌──────────────────────────────────────────────────────┐
│ [ロゴ]    メニュー(管理者用)  氏名／ログアウト│ ← ヘッダー（ログイン情報表示あり）
├──────────────────────────────────────────────────────┤
│ [受注管理] [マスタ] [システム]                        │ ← メニュータブ
├──────────────────────────────────────────────────────┤
│ ┌列1─────────┐ ┌列2─────────┐ ┌列3─────────┐        │
│ │[受注一覧]     │ │              │ │[バッチ一覧]   │        │
│ │[受注データ…]  │ │   (カードなし) │ │  …(空き枠)   │        │
│ │  …(空き枠)   │ │              │ │              │        │
│ └──────────┘ └──────────┘ └──────────┘        │
├──────────────────────────────────────────────────────┤
│                      フッター                          │
└──────────────────────────────────────────────────────┘
（受注管理タブの例。各列は7スロット固定で、余りは `halu-menu-item-blank`
　（project.cssで`display:none`）の不可視ボタンで埋める）
```

StartMenuとの構造上の違い（HTML実装より）：**メニュー項目の構成差は「マスタ」タブと「システム」タブに集約された**（管理者のみがユーザ一覧・システム用テーマ設定に到達できる。下表参照）。受注管理タブはStartMenuと同一構成

**A-007の判断変更（2026-08-02・C-043）**: 2026-07-31時点では「OrderUpload・BatchListがAdminMenuに無いのは意図した設計」と依頼者が確認していた（承認記録簿A-007）。C-043のメニュー再編で依頼者が**両画面をAdminMenuにも掲載する**と決定したため、この構成差は解消した（A-007の当該判断は失効）。

## 4. 操作

| 操作 | キー | 動作 | 遷移先 |
|------|------|------|--------|
| メニュータブ切替 | - | クリックしたタブの内容を表示し、選択中タブ名をセッションストレージに保存する（再訪時に復元） | - |
| メニュー項目クリック | - | クリックした項目のアクセスログを登録（userinfo）した上で対象画面へ遷移する | 各メニュー項目のname属性に設定された画面（3章参照） |
| ログアウト（ヘッダー右上） | - | ログオフのアクセスログ（`term`。画面名「ログオフ（メニュー終了）」）を記録した後、セッションストレージを全クリアし、Loginへ直接POST遷移する（D-002/C-001・Issue #27） | Login |

## 5. 特記事項

- 実装（AppSpec・controller/model/view・Json定義）はStartMenuと完全に同一パターンであり、`init`/`userinfo`/`term`の3トランザクション、`ログ情報`テーブルへのアクセスログ登録、ヘッダー右上のログアウトで`term`（ログオフ記録）を送る点（Issue #27。旧ログアウトボタンとEscキー経路は撤去済み）もStartMenuと同様。詳細はStartMenu.mdの特記事項を参照。
- **本画面固有のdataset**：`header`レコードは`ダミー`という名称のプレースホルダ項目のみを持つ（StartMenuと同一）。
- **freesql／doRun**：本画面では使用していない（`genesql`のみ）。
- **疑義（修正禁止・報告のみ）**: 3.1（受注管理タブ）に「取込エラー一覧」（OrderUploadErrorList）のカードが記載されていないが、実装（`AdminMenu/index.html`）には当該カードが存在し、common.md 1.1・OrderUploadErrorList.md 5章も掲載済みとしている（C-041）。設計書の記載漏れ。
- **疑義（修正禁止・報告のみ）**: 3.2（マスタタブ）は「商品一覧登録」を遷移先なしの非活性カードとしているが、実装では`name="Sample/Html/Apps/ProductListMainte"`が設定され`disabled`も外れている（common.md 1.1・ProductListMainte.md 5章のとおり2026-08-04に有効化済み）。設計書の記載が実装より古い。
