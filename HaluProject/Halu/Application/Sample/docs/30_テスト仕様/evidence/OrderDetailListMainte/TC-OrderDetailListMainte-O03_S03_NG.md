## O03 NG（明細行クリックで選択状態にならない）

- 手順: 明細1行目（既存行）・4行目（空行）の td（削除セル／商品名称セル／明細番号セル）をクリック
- 観測: クリックしたセルの属する tr・td に `table-success` クラスが付与されない（ハイライトなし）。`sessionStorage.getItem('明細番号')` は `"undefined"`、`sessionStorage.getItem('クリック行')` も `"undefined"`
- 原因切り分け: `singleRecordForm.controller.mixin-1.0.0.js` の `onテーブル行クリック` が行位置を `event.currentTarget.parentNode.parentNode.rowIndex` で取得している。イベントはappspecで `["#mainTable td","click","onテーブル行クリック"]` に束ねられており `currentTarget` は td 要素になるため、td→tr→tbody とたどる2段の `parentNode` では tr 要素ではなく tbody 要素に到達し、`rowIndex` が undefined になる。また `singleRecordForm.view.mixin-1.0.0.js` には行クリックの表示処理（ハイライト付与）自体が定義されていない。比較として `multiTableListForm.controller.mixin` は `event.currentTarget.parentNode.rowIndex`（td→trの1段）で取得し、`multiTableListForm.view.mixin`・`dataSelectionDialog.view.mixin` の `onテーブル行クリック` が `table-success` を付与・除去している
- ブラウザコンソール: エラーなし
- 業務影響: 本画面では選択行に対する後続の遷移・操作は無い（削除は行ごとのチェックボックスで指定するため）ため、業務影響は無い
- 判定: NG。変更管理台帳 C-071 起票（依頼者承認済み・同日修正実施。修正後の再テストはメインセッションが別途実施）

## 合計金額表示不具合の切り分け（S03／S08／追加確認）

- S03: 明細番号2の削除チェックをONにして`#実行`→2行目がDELETEされ、再照会の明細は明細番号1・3の2行（DBも2行、`受注金額合計`=3600で正しい）。**ただし画面の再表示ではヘッダ合計金額が4,200と表示される（正3,600。差分600＝削除された明細番号2の受注金額）**
- S08: 残る明細番号1・3を同時に削除チェックして`#実行`→2行ともSQLエラーなくDELETE（明細0件、`受注金額合計`=0で正しい）。**再表示のヘッダ合計金額は600と表示される（正0。差分600＝削除された最後の行の受注金額）**
- 追加の切り分け操作: 明細1行（800円）の状態から2行目にST002・数量1を追加して`#実行`→合計1,600（正）。2行目に削除チェックを入れると画面表示は800（正・S05相当）に即時再計算されるが、そのまま`#実行`すると再照会後の明細は1行のみなのに**画面のヘッダ合計金額は1,600のまま**（正800）。同時点のDB `受注ヘッダ.受注金額合計` は800で正しい
- 画面を出直す（`#戻る`→受注一覧の表示は正しい金額→再度`#訂正`/`#照会`で本画面に戻る）と、いずれのケースも正しい合計金額が表示される
- 規則性: 削除を含む`#実行`の応答後の再表示に限り、ヘッダ合計金額が「削除後の正しい合計＋削除された行の中で最後に処理された行の受注金額」になっている（S03: 3,600+600=4,200、S08: 0+600=600、追加確認: 800+800=1,600）
- コンソールエラー: なし。DB・後続処理への影響なし（表示のみの不具合）
- 判定: NG（表示のみ）。変更管理台帳 C-072 起票（依頼者承認済み。原因調査・修正は並行対応中の別セッションが担当し、マージ前に台帳へ追記）
