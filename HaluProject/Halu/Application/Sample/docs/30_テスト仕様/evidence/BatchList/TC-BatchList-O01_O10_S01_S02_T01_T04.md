## S02 delete の正常実行（子→親の順の物理削除）

削除前スナップショット（バッチ管理ＩＤ22）:

```sql
SELECT COUNT(*) FROM バッチ管理 WHERE バッチ管理ＩＤ = 22;           -- 1
SELECT COUNT(*) FROM バッチ分割管理 WHERE バッチ管理ＩＤ = 22;       -- 3
SELECT COUNT(*) FROM バッチキー管理 WHERE バッチ管理ＩＤ = 22;       -- 1
SELECT COUNT(*) FROM バッチパラメータ管理 WHERE バッチ管理ＩＤ = 22; -- 1
```

- BatchDivisionListから`#戻る`で戻った後`#再表示`→バッチ管理ＩＤ22を選択→`#処理削除`→確認ダイアログで今度は`#executeDialogYES`をクリック
- 応答: `#serverDialog`「サーバ処理確認」「削除処理は正常に終了しました。」
- 一覧が再照会され、バッチ管理ＩＤ22の行が消え「1/1ページ(6件)」になることを確認

削除後スナップショット:

```sql
SELECT COUNT(*) FROM バッチパラメータ管理 WHERE バッチ管理ＩＤ = 22; -- 0
SELECT COUNT(*) FROM バッチキー管理 WHERE バッチ管理ＩＤ = 22;       -- 0
SELECT COUNT(*) FROM バッチ分割管理 WHERE バッチ管理ＩＤ = 22;       -- 0
SELECT COUNT(*) FROM バッチ管理 WHERE バッチ管理ＩＤ = 22;           -- 0
SELECT バッチ管理ＩＤ FROM バッチ管理 ORDER BY バッチ管理ＩＤ;
-- 結果: 5, 17, 18, 19, 20, 21（バッチ管理ＩＤ22のみ消え、他は無傷）
```

- `BatchList_delete_sql.json`のsqls配列順（バッチパラメータ管理→バッチキー管理→バッチ分割管理→バッチ管理）どおりに子→親の順で物理削除されていることを確認。他のバッチ（21・既存履歴5,17,18,19,20）は無傷
