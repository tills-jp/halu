# テストデータ: 受注データアップロード（OrderUpload）

受注データアップロード画面（OrderUpload）の動作確認用CSVです。C-045（CSV取込の商品コード対応）で確定したレイアウトに準拠し、C-041（ＣＳＶ取込エラーレポート）の取込前チェックに対応しています。

| 項目 | 内容 |
|------|------|
| 作成日 | 2026-08-05 |
| 関連C番号 | C-045（受注ＣＳＶ取込の商品コード対応）、C-041（ＣＳＶ取込エラーレポート＝取込前チェックの拡張・エラー明細の記録） |
| 関連テスト仕様書 | `../OrderUpload_テスト仕様書.md`（S01〜S09・O09・T02）、`../OrderUploadErrorList_テスト仕様書.md`（S01〜S06）、`../BatchOrderUpload_テスト仕様書.md`（N01ほか） |
| 文字コード | UTF-8（BOMなし）。`OrderUpload_model.readLines`が`encoding='UTF-8'`で開くため他の文字コードは不可（Shift_JISで保存すると「ＣＳＶファイルを読み込めませんでした。文字コードがＵＴＦ－８か確認してください。」＝MSG-017になる。C-041） |
| 改行 | LF（CRLFでも可。各項目を`strip()`しているため） |

## CSVレイアウト（11列・1行目はヘッダ行として読み飛ばす）

| 列 | 項目 | 備考 |
|:--:|------|------|
| 1 | 受注番号 | 10桁以内。既存の受注番号と同じ場合は受注ヘッダの登録がスキップされる（重複防止） |
| 2 | 明細番号 | 受注番号との複合キー |
| 3 | 顧客ＩＤ | 顧客マスタに存在するＩＤ（FK制約あり） |
| 4 | 受注日 | YYYYMMDD（8桁のときのみYYYY/MM/DDへ変換される） |
| 5 | 受注金額合計 | 受注ヘッダへそのまま登録される（明細の合計との整合はCSV作成側の責任） |
| 6 | **商品コード** | **C-045で商品名称から置き換えた列**。商品マスタ（削除フラグ='0'）との完全一致で名寄せする |
| 7 | 納期日 | YYYYMMDD |
| 8 | 受注数量 | |
| 9 | 受注単価 | **CSVの値がそのまま受注明細へ入る**（商品マスタの標準単価では上書きしない） |
| 10 | 受注金額 | 受注数量×受注単価（計算はCSV作成側の責任） |
| 11 | 備考 | 空でも可（末尾のカンマは必要） |

**商品名称はCSVに含めません。** 受注明細の商品名称は商品コードで特定した商品マスタから転記されます（受注時点のスナップショット。画面の商品選択＝C-044と同じ方式）。

**現在マスタに登録されている商品コード**: `ST001`〜`ST008`（文具）、`FD001`〜`FD004`（飲食料品）。最新は商品一覧登録画面で確認してください。

### 取込前チェック（C-041）

取込時に以下を全件チェックし、**1件でもエラーがあれば全件中止**します（明細は取込エラー一覧で確認）。

| 区分 | チェック内容 |
|------|------------|
| レイアウト | 列数が11列であること |
| 必須 | 受注番号・明細番号・顧客ＩＤ・商品コード |
| 型 | 明細番号・顧客ＩＤ・金額・数量は数値／受注日・納期日はYYYYMMDDの8桁（未入力は可） |
| 桁数 | 受注番号10桁以内・商品コード20桁以内 |
| キー重複 | ＣＳＶ内で（受注番号,明細番号）が重複しないこと |
| マスタ照合 | 顧客ＩＤが有効な顧客マスタに存在すること／商品コードが有効な商品マスタに存在すること |

**現在マスタに登録されている顧客ＩＤ**: `1`〜`6`（顧客一覧登録画面で確認できます）。

| 1 | ST002 | （正常。ただし全件中止のため取り込まれない） |

**期待結果**（C-041で変更）

2. **受注ＣＳＶは0件になる**（C-041で変更。従来はロールバックにより「アップロード前の内容のまま」だったが、エラー明細をコミットして残すため、取込の打ち消しをDELETE文で行う方式へ変わった。受注ＣＳＶは永続データではないステージングのため業務影響はない）
3. **受注ヘッダ・受注明細は1件も増えない**（正常な1行目も登録されない）

5. **サーバー上のアップロードファイルは残る**ため、商品マスタを直したあと（同じ画面のまま）**CSVを再アップロードせずに「実行」だけで再取込できる**。画面を出入りするとファイル名がクリアされるため再アップロードが必要

## 使い方

1. ログイン（`http://localhost:8001/Application/Sample/Html/Apps/Login/index.html`）
2. メニューから「受注データアップロード」を開く
3. CSVをドラッグ&ドロップ（または「Open the file Browser」から選択）→自動アップロード
4. 「実行」（F1）→確認ダイアログで「は い」

**注意**: 1つの画面で選択できるファイルは1件だけです（`複数のファイルは選択できません。`）。別のファイルを試すときは「戻る」でメニューへ抜けてから画面を開き直してください。

**バッチサーバーの起動が必要**です（Docker環境では`app`サービスに同梱。`docker compose up -d`で起動済みなら追加操作は不要）。

## 後始末（正常系を流したあとに実行）

テスト用の受注番号は`TS`で始めているため、以下で検証前の状態に戻せます。

```bash
docker compose exec db psql -U postgres -p 55432 -d sample -c "delete from 受注明細 where 受注番号 like 'TS%';" -c "delete from 受注ヘッダ where 受注番号 like 'TS%';" -c "delete from 受注ＣＳＶ;" -c "delete from 受注ＣＳＶエラー;"
```

バッチ管理系の実行履歴（バッチ管理・バッチ分割管理・バッチキー管理・バッチパラメータ管理）も消して完全に戻す場合は、対象のバッチ管理ＩＤを確認してから4テーブルを削除してください（バッチ一覧画面の見た目を検証前に戻したいときのみ。実行履歴として残しておいても業務データには影響しません）。

デモ用データ（受注ヘッダ13件・受注明細26件・商品12件・顧客6件）は、この後始末だけで元の状態に戻ります。
