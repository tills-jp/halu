## 1. テストID体系と網羅基準

テスト仕様書標準（画面用）に従う（V=入力チェック / O=画面操作 / S=検索・CRUD / T=画面遷移。業務シナリオはアプリ単位の別冊）。

**V分類の対象外**: テーマコード・テーマ名称・使用の3項目すべて。テーマコード・テーマ名称は`input`要素に`disabled`属性が付与されており（index.html）、ブラウザ上でユーザーが値を入力すること自体ができない読み取り専用項目である。使用はラジオボタン（自由入力ではない）である。validation.jsonにはいずれも桁数ルールの定義があるが、画面上で実際にテキスト入力・書式チェックを起こす手段が無いため、V分類のテストケースとして成立しない（ドラフトのV01〜V04は、validation.jsonにルール定義があることのみを根拠にした生成ツールの誤検知であり削除した）。

## 2. テストケース

本画面の全項目（テーマコード・テーマ名称・使用）が読み取り専用またはラジオボタンであり、ユーザーによる自由入力が発生しないため、V分類の該当ケースは無い（対象外の理由は1章参照）。

**別冊（シナリオテスト仕様書）への申し送り**

- 本画面での使用テーマ変更（実行）後、実際に画面テーマ（CSS）が反映されるのはログイン時（Login）であるため、「テーマ変更→再ログインで画面テーマ反映の確認」は複数画面に跨るシナリオテスト仕様書（別冊）で扱う。
- 全件洗い替え（DELETE ALL→INSERT）方式は、削除と再挿入の間に他ユーザの同時実行があった場合の整合性（一時的なテーマ消失）が設計書5章で考慮事項として指摘されている（旧AI補完マークはA-010承認で解除）。マルチユーザ同時操作時の挙動は画面単体テストの範囲外のため、必要であれば非機能要件・別冊シナリオでの検討を推奨する。
